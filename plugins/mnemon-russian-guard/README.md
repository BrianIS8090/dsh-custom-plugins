# Mnemon — автоматическое восстановление русского интерфейса

Отдельный отключаемый плагин `@local/mnemon-russian-guard@1.0.0`. Он восстанавливает проверенный русский перевод после совместимых обновлений пяти клиентских пакетов Mnemon и не является официальным выпуском авторов upstream.

Собственный код остаётся `UNLICENSED`. Словари и производные upstream-данные в `data/plans.json` распространяются с отдельным MIT-уведомлением в `NOTICE.md`.

## Как работает

- При запуске, изменении графа клиентских плагинов и периодически получает пути только через `clientModules.clientPath()`.
- Обрабатывает строго `dsh-mnemon` и `dsh-mnemon-source-runtime/documents/memory-spaces/skills`.
- Проверяет имя пакета, штатный `./client` export, реальный путь, стабильность файла, anchors и синтаксис результата.
- Применяет перевод только к строковым литералам с точно совпадающим проверенным английским текстом. Новые или изменённые строки остаются английскими и перечисляются в диагностике. Код словарей обновляемого пакета на Host не выполняется.
- Изменяет только клиентский JS. Не вызывает memory API, не меняет память, провайдеры, настройки и серверный код.
- Перед записью сохраняет оригинал по SHA-256 и заменяет файл через rename в той же директории, не изменяя общий hardlink pnpm.
- После записи вызывает `clientModules.rebuilt(id)`. При отключении восстанавливает только собственные точные байты и не перезаписывает более новое внешнее обновление.

Рабочее состояние находится в `<profile>/.mnemon-russian-guard/`: `status.json`, `journal.json` и `originals/<sha256>.js`. Это локальные runtime-данные, которые не следует коммитить.

## Установка

1. Соберите и установите локализованный Starter из sibling `../mnemon-russian` по его README.
2. Установите этот каталог как локальный плагин DSH и включите **Mnemon — авторусификатор**. Runtime-зависимостей npm нет; `data/plans.json` самодостаточен.
3. После обновления клиентских сборок может понадобиться обновление страницы. Если менеджер обновлений требует полный перезапуск Harness, перезапуск обязателен.

Требуется Node.js `>=20` и DSH `>=0.2.0-rc.2 <0.2.1-0 || >=0.2.1-rc.1 <0.3.0-0`. При отсутствии ожидаемых методов `clientModules` плагин пропускает обработку с предупреждением.

## Перегенерация и тесты

Сначала выполните `prepare`, `build` и `build-sources` в sibling `../mnemon-russian`. Затем из этого каталога:

```powershell
node scripts/prepare.mjs
node --test --test-isolation=none test/*.test.mjs
node --check index.js
node --check controller.mjs
node --check transform.mjs
```

Тесты используют только verified `../mnemon-russian/dist/work`: реальные bundles, ru/en/zh, неизвестные/изменённые строки, несовместимые anchors/синтаксис, идемпотентность, смену пути/байтов, registry cache, rollback, restart и hardlinks. Controller-тесты создают и удаляют собственные временные каталоги ОС. Live-проверки и изменение установленного профиля в публичный набор не входят.

## Границы гарантий

Это проверяемые патчи известной структуры, не универсальный переводчик произвольной будущей версии. Крупное изменение компоновки требует обновления адаптера. Guard не выполняет автоматический машинный перевод и ничего не отправляет внешним сервисам.

Общей транзакции с отдельным npm-процессом нет: guard ожидает стабилизации и повторно сверяет путь, manifest и hash непосредственно перед commit, но не обещает атомарность относительно процесса, изменяющего тот же каталог ровно в этот момент.
