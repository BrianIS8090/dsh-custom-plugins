# Установка плагинов каталога агентом

Цель: агент сам собирает, устанавливает и проверяет плагины из этого репозитория на **DeepSeek Harness Desktop `0.2.2-rc.5`**. У пользователя он спрашивает только выбор и данные, которых нет в репозитории. Состав — в [README](README.md), внешние пакеты — в [EXTERNAL](docs/EXTERNAL.md), настройка — в [CONFIGURATION](docs/CONFIGURATION.md).

## Порядок работы

1. **Опрос.** Одним `ask_user_question` с `multi_select: true` спросите, какие плагины ставить. Варианты — строки таблицы в [README](README.md) и пакеты из [EXTERNAL](docs/EXTERNAL.md). Вторым вопросом в той же карточке задайте профиль: рабочий или отдельный тестовый. Затем одной карточкой задайте вопросы из раздела «Спросить» выбранных плагинов. Не спрашивайте то, что можно узнать из `list_bundles` или репозитория.
2. **Предусловия.** Проверьте сами, ничего не поручая пользователю:
   - версия DSH: `$env:DSH_INSTALL_DIR\package.json`, поле `version`. Ниже `0.2.2-rc.5` — остановитесь и сообщите, какие плагины несовместимы;
   - Node.js 24.x не ниже 24.15 и pnpm 11.9.0 — только для плагинов со сборкой (Russian Kanban, Mnemon Russian). Нет нужной версии — сообщите, что нужно поставить, и продолжайте с остальными плагинами;
   - репозиторий лежит в постоянной папке: `link:`-установка ссылается на каталог, его нельзя перемещать. Если репозиторий во временной папке, предложите перенести его до установки.
3. **Текущее состояние.** Вызовите `plugin_manager` `list_bundles` один раз. По нему определите уже установленные версии и конфликты из карточек ниже.
4. **Сборка.** Выполните шаг «Собрать» каждого выбранного плагина. Ошибка сборки или тестов — этот плагин не ставьте, остальные продолжайте.
5. **Установка.** Для каждого плагина вызовите `plugin_manager` `install_bundle`, `target` — **абсолютный** путь к каталогу `plugins/<имя>` (для Mnemon — к `.tgz`), для внешнего пакета — точный spec из [EXTERNAL](docs/EXTERNAL.md). Корень репозитория не передавайте: в нём нет bundle.
6. **Результат установки.** Читайте `application` и `warnings` каждого ответа:
   - `applied` — проверьте плагин сразу;
   - `restart-required` — соберите все такие плагины, затем один раз попросите пользователя выйти из Desktop через **Quit** и запустить его снова. Сами процесс Desktop не завершайте. После перезапуска проверьте в новой сессии;
   - `pendingBuilds` — покажите пользователю имена пакетов и спросите разрешение; `approvedBuilds` передавайте только после явного «да»;
   - `failed`, `incompatible-version`, `overridden` — не обходите. Сообщите причину; `set_version_exemption` не используйте.
7. **Настройка.** Выполните раздел «Настроить» карточки. Правила для ключей — в разделе «Секреты».
8. **Проверка и отчёт.** Выполните «Проверить». В конце дайте таблицу: плагин, версия, состояние, что проверено, что осталось пользователю.

Если `plugin_manager` недоступен или вызов отклонён, не меняйте пресет и не пишите профиль вручную. Соберите плагины, затем дайте пользователю абсолютные пути для **Plugins → Add plugin → Install a third-party plugin** и продолжите с шага 6 по его подтверждению.

## Секреты и адреса

- Ключи API пользователь вводит только в форме плагина. Не просите ключ в чате и не принимайте его оттуда; если пользователь прислал ключ в чат, не используйте его и посоветуйте отозвать.
- Адреса сервисов (base URL, origin) можно спросить в чате. Проверьте формат до передачи пользователю: Codex Image — `https://…/v1`, Subscription Quota — HTTPS origin без пути, параметров и учётных данных.
- У агента нет инструмента записи настроек плагина. Не редактируйте `cordis.patch.yml`, `package.json` профиля и хранилище учётных данных. Дайте пользователю точный путь к форме и готовое значение адреса для вставки.
- Не пишите ключи, личные адреса и данные профиля в репозиторий, отчёты и журналы.

## Карточки плагинов

Команды «Собрать» выполняйте из каталога плагина. Где сборки нет, пакет ставится как есть: собранные клиентские файлы лежат в Git.

### Agent Team Monitor, Agent War Room, Running Session Preview

- Собрать: не нужно. Перед установкой запустите `npm test`; для War Room сначала `pnpm install --frozen-lockfile`.
- Спросить: ничего.
- Настроить: ничего. Agent Teams входит в DSH и включается в меню модели корневой сессии.
- Проверить: Team Monitor показывает участников и сообщения командной сессии; `/war-room <вопрос>` открывает представление War Room; Preview показывает последнее действие работающей сессии в боковой панели.

### Russian Kanban

- Собрать: `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm build`, `pnpm test`.
- Спросить: есть ли доска `.dsh-kanban.json`, которую нужно сохранить. Если есть, сделайте её копию рядом (`.dsh-kanban.backup-<дата>.json`) до установки.
- Конфликт: `@alpacachen/dsh-kanban` использует тот же маршрут `/api/kanban` и инструменты `kanban_*`. Если `list_bundles` его показывает, спросите разрешение и выключите его через `set_bundle` с `enabled: false` до установки. Не удаляйте его и не трогайте доску.
- Настроить: ничего.
- Проверить: в новой сессии вызовите `kanban_get_board`, создайте синтетическую карточку, перенесите её, удалите. `*` в поле ввода открывает выбор задач.

### 7LAMP Harness

- Собрать: не нужно; `npm test` перед установкой.
- Спросить: ничего.
- Проверить: попросите пользователя переключить светлую и тёмную темы и подтвердить, что текст читаем.

### Kimi Cost Meter

- Спросить: подключён ли Kimi Code. Если нет, плагин не ставьте и сообщите почему.
- Настроить: собственного ключа нет; плагин читает credential Kimi Code из **Settings → Models**. Если маршрут Kimi не настроен, попросите пользователя добавить его там; ключ вводит он сам.
- Проверить: на маршруте Kimi рядом с моделью видна плашка остатков.

### Subscription Quota

- Спросить: HTTPS origin сервиса CPA Key Billing (например `https://billing.example.com`).
- Настроить: после полного перезапуска пользователь нажимает **Subscription quota · Настроить** рядом с моделью, вставляет origin, который вы проверили, вводит свой ключ CPA и нажимает **Сохранить и проверить**.
- Проверить: индикатор показывает остаток вместо «Настроить».

### Codex Image

- Спросить: адрес OpenAI-совместимого Images API с `/v1` и есть ли другой плагин изображений (например `dsh-image-gen`). Если есть, спросите, выключить ли его, чтобы агент не путал инструменты.
- Настроить: пользователь открывает **Plugins → Codex image (GPT Image)**, вставляет адрес, вводит ключ, нажимает **Сохранить**, затем **Проверить подключение**. Перезапуск не нужен.
- Проверить: `gpt_image_generate` с промптом без личных данных; файл появляется в `generated-images`.

### Mnemon Russian и Guard

- Собрать: в `plugins/mnemon-russian` выполните `npm test`. Он чистит `dist`, скачивает upstream по SHA-512, собирает и проверяет `dist/dsh-mnemon-0.5.42-ru.3.tgz`.
- Спросить: стоит ли уже `dsh-mnemon` и нужно ли сохранить его память. Перед заменой предупредите, что фоновые задачи Mnemon делают отдельные запросы к модели.
- Установить: сначала `.tgz` по абсолютному пути, затем полный перезапуск, затем каталог `plugins/mnemon-russian-guard`.
- Проверить: в `list_bundles` один `dsh-mnemon`; интерфейс Mnemon на русском; синтетическая запись сохраняется и находится поиском.

Kimi Cost Meter, Subscription Quota и Codex Image перед установкой проверяются своим `npm test`.

### Внешние пакеты

- Установить: `install_bundle` с точным spec из [EXTERNAL](docs/EXTERNAL.md). Код пакетов в этот репозиторий не копируйте.
- Спросить: для MCP Panel — какие MCP-серверы подключить. Адрес и команду сервера можно получить в чате, токены пользователь вводит в форме панели. Computer Use Win ставьте только по явному запросу и предупредите, что снимки экрана и OCR могут содержать личные данные.
- Проверить: пакет активен в `list_bundles`; у MCP Panel подключённый сервер отвечает на проверку инструментов.

## Проверка перед публикацией

Этот раздел нужен только при изменении репозитория. Из чистого checkout используйте Node 24.x (не ниже 24.15) и pnpm 11.9.0:

```powershell
pnpm --dir plugins/agent-war-room install --frozen-lockfile
pnpm --dir plugins/russian-kanban install --frozen-lockfile
npm test
```

Проверяйте весь отправляемый снимок и все коммиты ветки. Запустите `npm run audit -- <путь-к-чистому-экспорту>` и независимый сканер секретов с редактированием значений в выводе. Отдельно проверьте конечные точки, приватные пути, внешние зависимости и сгенерированные файлы. Непроверенная находка блокирует публикацию. Профили, базы, ключи, личные адреса, снимки, диагностику и архивы `.tgz` не публикуйте.
