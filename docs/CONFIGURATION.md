# Настройка после установки

Это безопасная пользовательская последовательность для эталонной конфигурации DeepSeek Harness `0.2.2-rc.1`. Все действия выполняются через GUI. Документ не является выгрузкой профиля и не содержит готовых YAML-замен для `cordis.patch.yml` или ручных правок `package.json`.

Названия страниц могут немного отличаться между локализациями. Если Host сообщает `restart-required`, сначала сохраните работу и выполните предложенный перезапуск; browser-половину затем обновите перезагрузкой страницы.

## 1. ChatGPT/Codex OAuth и отображение квоты

1. Убедитесь, что `dsh-codex-subscription@3.2.6` установлен и включён.
2. Откройте **Settings → Codex → Start**.
3. Выберите вход через ChatGPT и завершите OAuth в браузере. Нужен аккаунт, которому в данный момент доступен Codex.
4. Если browser callback не завершился, повторите через **device-code sign-in**. При сетевой ошибке проверьте HTTPS-соединение и proxy; не передавайте диагностические URL или коды другим людям.
5. Вернитесь в беседу и выберите доступную Codex-модель в model picker.
6. В **Settings → Codex → Start** найдите отображение квоты рядом с composer и выберите **Percentage / Проценты**. Эталонное значение настройки — `quickQuotaMode=percent`.

Для обычного чата OpenAI API key и Codex CLI не нужны. Независимые Codex-подзадачи являются отдельной opt-in возможностью и не должны активировать несовместимый `@deepseek-ai/dsh-subagent-codex@0.2.1-rc.5`.

**Граница безопасности:** sign-in URL, authorization/device codes, полный redirect/callback URL, access/refresh tokens, account identifiers и сырые ответы авторизации не копируются в документацию, issues или публичные журналы.

## 2. Kimi credential для `dsh-cost-meter`

`dsh-cost-meter` не требует отдельного ключа в собственном интерфейсе: он использует Kimi credential, уже сохранённый DSH.

1. Откройте **Settings → Models**.
2. Настройте Kimi route, поддерживаемый установленной версией `dsh-cost-meter`. Идентификатор совместимого маршрута сверьте с README своей сборки; его приватные параметры в этот документ не входят.
3. Выберите один способ аутентификации:
   - сохраните **Kimi Code API key** через настройки Models;
   - либо выполните **Sign in with Kimi Code** через OAuth.
4. Выберите Kimi-модель в беседе. Рядом со штатными счётчиками появится плашка остатков лимитов.
5. Нажмите на плашку для принудительного обновления; наведение показывает окна лимитов и сбросы.

Плагин читает credential из штатного credential store и может обновлять OAuth access token через сохранённый refresh token. Для работы нужны публичные сервисы `api.kimi.com` и, при OAuth-refresh, `auth.kimi.com`.

Endpoint лимитов неофициальный: его изменение может оставить плашку без данных, не ломая остальной интерфейс. Ключи и OAuth-записи не копируются в конфигурационные файлы проекта или документацию.

## 3. Отдельный CPA Key Billing для `subscription-quota`

CPA Key Billing — это **отдельный credential**, а не повторное использование Kimi, ChatGPT или DeepSeek key.

1. Рядом с выбранной моделью нажмите **Subscription quota · Настроить**.
2. Введите **Billing origin** вашего сервиса в формате `https://billing.example.com`. Значения по умолчанию нет; укажите HTTPS origin без пути, query, fragment и учётных данных в URL.
3. Введите свой **CPA Key Billing API key**.
4. Нажмите **Сохранить и проверить**.
5. После успешной проверки индикатор покажет остаток/лимит. Подробности открываются нажатием; **Обновить** запрашивает свежий снимок.

Важно:

- Индикатор показывает квоту именно введённого CPA key, независимо от выбранной модели. Он не утверждает, что текущая модель использует этот же ключ.
- Проценты означают **остаток**, а не расход.
- Ключ хранится в штатном credential store Harness, не добавляется в Cordis config, URL или browser local/session storage и не возвращается браузеру после сохранения.
- Billing origin сохраняется отдельно в credential reference `SUBSCRIPTION_QUOTA_BILLING_ORIGIN`; публичный пакет не содержит адреса по умолчанию.
- Не вставляйте ключ в `AGENTS.md`, Markdown, tickets, screenshots или diagnostics.
- Отключение плагина сохраняет ключ. Если требуется его удалить, сначала используйте отдельное действие **Удалить ключ**.

## 4. DeepSeek Account для фоновых задач памяти

Фоновые операции памяти могут использовать не основной маршрут беседы, а отдельный DeepSeek Account route.

1. Откройте **Settings → Models** или страницу аккаунта и выполните вход в **DeepSeek Account** штатным способом.
2. В настройках используемого memory plugin найдите маршруты фоновых операций.
3. Для доступных полей summarize, dream, dream summary, sleep, entity extraction или background task agent выберите **DeepSeek Account** и `deepseek-flash`. Если версия plugin предоставляет только общий background route, настройте его; не создавайте вручную отсутствующие поля.
4. Сохраните настройки и выполните одну нечувствительную проверочную операцию. Убедитесь в аудите plugin, что фоновый запрос завершился успешно.
5. Основную модель беседы менять не требуется: background routing является самостоятельной настройкой.

Такие операции создают дополнительные платные model requests и могут отправлять фрагменты памяти или диалогов выбранному провайдеру. Не включайте обработку приватных данных без проверки этого маршрута и политики хранения.

Содержимое памяти, базы, audit logs и пользовательские записи в публичную конфигурацию не экспортируются.

## 5. Тёмная тема и перевод reasoning

### Тема

Откройте **Settings → General → Theme** и выберите **Dark**. Это только визуальное предпочтение, не часть пакетной установки.

### Reasoning translation

1. Откройте **Plugins** и включите **Reasoning translation** в Official.
2. Откройте настройки bundle.
3. Выберите:
   - **Provider:** `google`;
   - **Target language:** `ru`.
4. Сохраните и разверните строку reasoning, чтобы запустить перевод.

Исходное reasoning остаётся доступным и не переписывается в Session или model input. Перевод отправляет развёрнутые фрагменты reasoning выбранному сервису; в них могут быть код и личные сведения. Для Google не требуется отдельный login/API key, но доступность anonymous endpoint и rate limits не гарантируются.

## 6. Subagent и публичный plugin-market index

### Лимит активных субагентов

Откройте **Settings → Built-in plugins → Subagent** и установите **Max active subagents** равным `10`. Эталонное значение — `maxActiveSubagents=10`. Это ограничение параллелизма, а не обязательство создавать десять субагентов.

### Custom plugin indexes

1. В **Plugins → Experimental plugins** включите **Custom plugin indexes**.
2. Перейдите на вкладку **Discover**.
3. Добавьте публичный index:

   ```text
   https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json
   ```

4. Сохраните и дождитесь загрузки каталога.

Index — это источник метаданных, а не гарантия безопасности пакета. Перед установкой проверяйте пакет, версию, исходники, совместимость и запрашиваемые build scripts. Не добавляйте private index URLs с credentials или query tokens.

## 7. Краткая проверка результата

- Codex OAuth завершён, модель доступна, composer quota отображается в процентах.
- Kimi-плашка появляется только при выбранной Kimi-модели и использует credential из Models.
- `subscription-quota` проверяет отдельный CPA key и не выдаёт его за ключ текущей модели.
- Фоновая проверка памяти использует DeepSeek Account / `deepseek-flash` и не меняет основную модель беседы.
- Выбрана тёмная тема; reasoning translation использует Google и русский язык.
- Max active subagents равен `10`; публичный plugin-market index загружается в Discover.
- После Host-изменений выполнен требуемый перезапуск, browser-половина обновлена.

## 8. Что не экспортируется

Публичная конфигурация включает только нечувствительные версии пакетов, публичные ссылки и перечисленные пользовательские предпочтения. Не экспортируются:

- приватные model routes, base URLs, proxies и endpoints;
- API keys, OAuth tokens, authorization/device codes, callbacks и account identifiers;
- содержимое и базы памяти, embeddings, audit logs и история обработки;
- пользовательские skills и их локальные изменения;
- sessions, transcripts, session identifiers, preview/session tokens и diagnostics с личными данными;
- локальные пути и персональные настройки, не перечисленные явно в этом документе.

Не копируйте реальный `cordis.patch.yml` и не применяйте отдельные YAML-фрагменты как частичные replacements: profile override может заменить конфигурацию целиком. Для воспроизведения используйте последовательность GUI выше и штатный Plugin Manager.
